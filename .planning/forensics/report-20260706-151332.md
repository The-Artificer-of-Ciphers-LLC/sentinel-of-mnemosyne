**Root cause (source-level):**
- **Package:** `@opengsd/gsd-core` **v1.5.0-rc.3**
- **File:** `bin/lib/phase-id.cjs` → `extractPhaseToken(dirName)` (lines ~166–189)
- **Defect:** the token-collection loop (lines ~176–184) appends **every** consecutive hyphen-split segment whose first char is a digit:
  ```js
  const segments = rest.split('-');            // "46-6-rs-pipeline-orchestrator" → ["46","6","rs",...]
  for (const seg of segments) {
    if (/^\d/.test(seg)) tokenSegments.push(seg); // "46" kept, then "6" ALSO kept
    else break;                                   // stops at "rs"
  }
  // → token "46-6"  ≠  normalizePhaseName("46") === "46"  → phaseTokenMatches() fails
  ```
- **Trigger class:** any phase whose **slug starts with a single digit** (here "6 Rs …" → slug `6-rs-…` → dir `46-6-rs-…`). Letter-leading slugs (44, 45) are unaffected because the loop breaks on the first segment.

**Interpretation:** `/^\d/` cannot distinguish a legitimate zero-padded phase-token segment (`01`, `02`, always ≥2 digits) from a 1-digit slug word (`6`). The loop over-collects the slug's leading digit into the phase token.

## Root Cause Hypothesis

`extractPhaseToken` in `phase-id.cjs` over-greedily treats the slug's leading single-digit word as part of the phase number. Phase 46's roadmap-derived slug (`6-rs-pipeline-orchestrator`) is the first phase in this project to start with a digit, so it is the first to expose the latent bug. Every `gsd-tools` command that resolves a phase directory by number (`init.plan-phase`, `init.phase-op`, and by extension execute/verify/ship steps) will misfire for Phase 46 until fixed.

## Recommended Actions

1. **Upstream fix (open-gsd/gsd-core):** in `bin/lib/phase-id.cjs` `extractPhaseToken`, require a token segment to carry **≥2 leading digits** before collecting it, so slug-leading single digits break the loop:
   ```js
   const m = seg.match(/^\d+/);
   if (m && m[0].length >= 2) { tokenSegments.push(seg); } else { break; }
   ```
   Preserves multi-segment zero-padded sub-phase tokens (`02-01`) while rejecting 1-digit slug words. (Residual edge case: a slug leading with a ≥2-digit number, e.g. `2024-roadmap`, would still over-collect — worth a follow-up, but far rarer than the single-digit case.)
