**Interpretation (leading hypothesis):** The allow-rule `Write(.planning/*)` is a single-segment glob — `*` does not cross `/`, so it matches `.planning/FOO.md` but **not** the nested `.planning/research/SUMMARY.md`. In an interactive main context an unmatched Write would prompt the user for approval; in a **non-interactive subagent** there is no prompt channel, so an unmatched Write is denied — surfacing to the agent as "the runtime is blocking file writes for this role." Every write that succeeded matched the single-level pattern; the one that failed was nested.

**Counter-evidence (why MEDIUM, not HIGH):** the `gsd-debug-session-manager` subagent earlier appears to have updated `.planning/debug/vault-retrieval-past-context.md` (also two levels) without being blocked. Distinguishing these requires Claude Code runtime dispatch logs, which are not file-inspectable — so the exact mechanism cannot be confirmed from configuration alone.

## Root Cause Hypothesis

The synthesizer's write target (`.planning/research/SUMMARY.md`) is **nested two levels** under `.planning/`, but the project's auto-approve permission rule is `Write(.planning/*)` — a single-segment glob that does not match nested paths. A non-interactive subagent cannot fall back to an approval prompt, so the unmatched nested Write was denied. The agent correctly degraded by returning its content for the orchestrator to persist, so there was no data loss.

## Recommended Actions

1. **Broaden the permission glob** in `~/.claude/settings.json`: change `Write(.planning/*)` → `Write(.planning/**)` (and likewise `Read(.planning/*)` → `Read(.planning/**)`). This covers nested subagent writes (`research/`, `forensics/`, `phases/<n>/`, `debug/`) and removes this failure mode regardless of the exact dispatch mechanism — low-risk, since `.planning/` is already a trusted, git-ignored tree.
2. **No recovery needed for this incident** — `SUMMARY.md` is present and correct; the milestone artifacts are intact.
3. **Optional upstream report:** GSD research/synthesizer workflow templates instruct the agent to "write then commit." If GSD intends synthesizer-tier agents to be write-capable, the install-time default permission for `.planning/` should use `**`, not `*`. Worth a `bug:` note to `open-gsd/gsd-core`.

- **Glob-scoping hypothesis: REFUTED.** Nested `.planning/**` writes are not blocked — `Write(.planning/*)` is not the constraint.
- **Agent-type-restriction hypothesis: REFUTED.** `gsd-research-synthesizer` writes both flat and nested `.planning/` paths successfully on a fresh dispatch.

**Agent-definition audit (`~/.claude/agents/gsd-research-synthesizer.md`, lines 131–141):** the agent is explicitly instructed *against* the exact behavior it exhibited:
- "The `Write` tool is in your `tools:` allowlist; **there are no restrictions on it. Do not assume restrictions that the frontmatter does not impose.**"
- "Do NOT ask permission to write… Asking the orchestrator to do it instead is a **failure mode** that can cause downstream `SUMMARY.md not found` failures."
- "If the Write tool errors, **surface the actual error**… Do **not** silently fall back to returning content."

The original run violated all four. The reported "runtime is blocking file writes for this agent role" string appears nowhere in config or agent definition and was **not** a surfaced tool error.
