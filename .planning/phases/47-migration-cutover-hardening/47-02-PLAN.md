  <behavior>
    - record_restore_original(src, body): stores an inverse that re-writes `body` to `src` (undo of a notes-bound delete).
    - record_ops_move(src, dst, sidecar_key_moved): stores an inverse that relocates `dst`→`src` AND, if `sidecar_key_moved`, reverts the embedding-index key `dst`→`src` — as ONE entry (T-47-03: never restore file without sidecar).
    - record_backlink_rewrite(note_path, before_body): stores an inverse that restores `before_body` to `note_path` (undo of a D-03 backlink rewrite).
    - record_inbox_write(path, before_body): stores an inverse that restores the prior inbox queue body.
    - replay(vault): executes all recorded inverses in REVERSE (LIFO) order, each idempotently; a second replay is a no-op.
  </behavior>
  <action>
    Implement `RollbackLedger` holding an ordered list of inverse-op descriptors (a dataclass or tagged tuple per op kind). Each `record_*` appends a descriptor capturing exactly the state needed to reconstruct the inverse. `async def replay(self, vault)` iterates the list in reverse and dispatches each descriptor to its inverse: `restore_original` → `await vault.write_note(src, body)`; `ops_move` → `await vault.relocate(dst, src)` then (if `sidecar_key_moved`) read `EMBEDDING_INDEX_PATH`, rename key `dst`→`src` via `embedding_sidecar_index.decode_index_body`/`encode_index_body`, write it back; `backlink_rewrite`/`inbox_write` → `await vault.write_note(path, before_body)`. Make every inverse idempotent (guard on current state; a missing/already-restored target is a no-op, mirroring `detach_from_hub`). Do NOT swallow exceptions silently — log and continue replaying remaining inverses so a single failed undo does not strand the rest (best-effort full unwind), but surface an aggregate error. This module performs NO forward mutations and holds NO business logic beyond record + replay.
  </action>
