<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Discord/HTTP client → POST /vault/pipeline/start | Admin-only background-mutation trigger; unauthenticated/non-admin callers must be refused before any vault write. |
| pipeline run ↔ vault sweep (shared lockfile) | Two background mutators of `notes/` must be mutually exclusive to prevent write races. |
| inbox/vault content → six_rs completions → notes/ writes | Untrusted content drives LLM output that becomes durable notes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-46-01 | Elevation of Privilege | Admin-route bypass via a drifted `_is_admin_route` copy | high | mitigate | IMPORT `_is_admin_route` from `app.routes.note` (single source); route returns 403 for non-admins (Open Question 3, RESEARCH Security Domain V4) |
| T-46-04 | Denial of Service | Concurrent pipeline/sweep runs racing `notes/`, or a run wedging the lock | high | mitigate | Shared `acquire_sweep_lock`/`release_sweep_lock` (D-04) acquired before inbox read; `finally`-release; existing 1h stale-lock takeover; `run()` refuses cleanly with `SweepInProgressError` |
| T-46-05 | Tampering | LLM-driven writes landing malformed/non-compliant notes in `notes/` | high | mitigate | Reduce files `status: draft`; Verify gates Reflect/Reweave and requeues failures out of `notes/` (D-02, PIPE-07); every stage schema-validated; per-entry error isolation (Pitfall 10) |
| T-46-RETRY | Denial of Service | Verify-failure requeue looping forever | medium | mitigate | Bounded `VERIFY_RETRY_CAP`; at cap the entry stays in inbox marked `needs_attention` and is surfaced in the report — never silently dropped, never infinite (D-02) |
| T-46-INJECT | Tampering / Elevation of Privilege | Prompt injection via vault content read into any six_rs stage | high | mitigate | Untrusted content in user slot only; system prompts carry explicit DATA-ONLY framing (enforced in 46-04/46-05 stages this orchestrator drives) |
| T-46-DOS-BATCH | Denial of Service | Unbounded inbox size causing an unbounded run | medium | accept | Personal-vault scale; run is admin-triggered and user-invoked only (no scheduler — Pitfall 4); status is pollable so a long run is observable |
