<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any X-Sentinel-Key holder (e.g. pf2e) → core `POST /embeddings` | untrusted request body (`texts[]`) crosses into core |
| core route → embedding backend (via `ctx.embedder`) | vector computation is delegated to the configured backend |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-43-02-01 | Information Disclosure | `POST /embeddings` error path | high | mitigate | Catch only the typed `EmbeddingModelUnavailable` → generic 503; never echo litellm/httpx exception text (may embed `api_base`/`api_key`) — same T-42-08 precedent as `/provider/complete`; test asserts no base_url/api_key substring in the 503 body |
| T-43-02-02 | Denial of Service | `EmbeddingsRequest.texts` | medium | mitigate | `Field(min_length=1, max_length=_MAX_TEXTS)` + per-text `_MAX_TEXT_LENGTH` cap → 422 before the backend is called; bounds worst-case backend cost from one request |
| T-43-02-03 | Tampering / Elevation (SSRF) | `EmbeddingsRequest` schema | high | mitigate | Schema accepts ONLY `texts` — no `base_url`/`model`/`api_base` field; backend selection is core-owned (D-04), so a client cannot redirect the embedding call to an attacker host |
| T-43-02-04 | Spoofing | unauthenticated access to `/embeddings` | medium | mitigate | Existing global `APIKeyMiddleware` (`X-Sentinel-Key`) already covers every non-`/health` route including this one; test asserts 401 without the key |
| T-43-02-SC | Supply Chain | pip installs | low | accept | N/A — no new packages; the route imports only fastapi/pydantic (already pinned) and must NOT import any vendor SDK |
</threat_model>
