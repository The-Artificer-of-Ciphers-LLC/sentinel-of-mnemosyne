<objective>
Build the receiving end of the pf2e->core chat handoff: a narrow `POST /provider/complete` endpoint on sentinel-core that is a thin passthrough to `ctx.ai_provider.complete()` (no recall, no injection filter, no output scanner, no note filing), plus the `SentinelCoreClient.complete()` client method pf2e will call. This restores the "everything through Sentinel" gateway design for chat (D-09) and centralizes provider/fallback logic in core (SC-6).

Purpose: Give pf2e one authenticated core entrypoint for chat/completion so no module hardcodes an LLM endpoint or model. The endpoint intentionally does NOT reuse the /message pipeline — pf2e prompts already carry their own context, and mixing in the operator's Discord memory would be architecturally wrong. This endpoint is the receiving end of the accepted pf2e→core runtime dependency for chat (D-10), which is already provisioned via compose `depends_on: sentinel-core` (healthy).
Output: the route + request/response models, its main.py registration, and the shared client method.
</objective>
