<objective>
Replace the three drifted provider-name branch points with ONE table-driven `openai_compatible` backend registry, and add exo as a first-class entry alongside LM Studio (SC-2, D-01/D-02/D-03). Wire exo model resolution to exo `GET /state` running-instances (SC-4, D-07/D-08), give exo its own context-window registry branch (SC-5, Pitfall 4), and generalize fallback selection so any configured provider can be the fallback (SC-3, D-05).

Purpose: This is the architectural heart of the phase. The `exo-model-notfound-502` bug's root cause was ad-hoc per-provider conditionals silently defaulting to the wrong provider; the fix is data-driven selection, NOT another `if ai_provider == "exo"` patch. LM Studio migrates onto the same table (D-02) with explicit regression pinning.
Output: the provider table, exo discovery, the exo provider_map/registry entries, generalized fallback selection.
</objective>
