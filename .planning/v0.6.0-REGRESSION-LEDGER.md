milestone (Phases 44-47). Established in Phase 44 Plan 01 per Pitfall 1
discipline ("establish the ledger in the first v0.6.0 phase"). This is the

Append-only in shape: each later phase boundary adds its own check-in row
below rather than editing prior entries. Do not delete or weaken a prior

## 1. The Hot Gate — MEM-01..MEM-09

These nine requirements (validated across Phases 39-41, "The Second Brain"
milestone) are the hot regression gate. Every v0.6.0 phase boundary MUST
keep every one of these green — a MEM-0x characterization test going red
at any phase boundary is a phase-gate failure, not a note for later.

| Requirement | One-line contract | Phase 44 status |

## 3. D-05 — Accepted Transient (Phase 44 → Phase 47)

**Decision:** Between Phase 44 and Phase 47, existing top-level `journal/`,
`accomplishments/`, `learning/`, `references/` notes already in the vault
are **not** physically migrated by Phase 44. Phase 44's D-01 removes the
warm-tier carrier-namespace recency allowlist entirely (see MEM-09 row
above), so these pre-existing notes:

- **Remain warm-recallable** — `RecallConfig.exclude_prefixes` does not
  change in Phase 44; nothing about D-01/D-03 removes an existing note's
  warm-tier searchability.
- **Lose recency weighting immediately** — because the mechanism that used
  to boost recently-dated notes under these prefixes (place (b)) no longer
  exists anywhere in `recall.py`. New captures classified after Phase 44
  land under the NEW taxonomy (`inbox/` or `ops/...`) per `TOPIC_VAULT_PATH`;
  only the not-yet-migrated OLD top-level notes are affected.

**This is accepted and documented, not a silent regression:**

- It aligns with MEM-09's end state (recency weighting is Session-summary-only
  going forward — pre-existing carrier notes losing a mechanism that no
  longer conceptually applies to them is the intended direction of travel,
  not an oversight).
- It self-heals when Phase 47's migration cutover physically moves these
  notes under `ops/` (at which point they become warm-excluded entirely,
  consistent with every other `ops/`-filed note).
- **No throwaway compat shim is written in Phase 44** to preserve the old
  weighting behavior for these soon-to-be-migrated notes — per the locked
  D-05 decision, doing so would be scaffolding for a ~3-phase window with
  no reuse value past Phase 47.

This row is the artifact MIG-03 (Phase 47) verifies: at the migration
cutover boundary, confirm these top-level notes have been physically moved
under `ops/` and that no compensating shim was ever introduced in the
interim.
